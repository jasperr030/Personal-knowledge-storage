# 知识整理约定

## 内容和分类

生活、学习、兴趣、技术和个人工作经验均可收录。先写入 `inbox/` 也可以，目录按使用需求逐步整理。
一篇笔记围绕一个可复用主题；需要时链接其他笔记。不要为分类而拆成大量空目录。
现有服务会递归索引笔记仓库中非隐藏路径下的 Markdown；隐藏目录 `.templates/` 用来存模板。

## 建议格式

从 [通用模板](../.templates/note.md) 复制，填写一个唯一且稳定的 `id`。
`title`、`source`、`status`、`updated`、`tags` 都是现有服务可读取的字段；目录与标签都可用中文。
缺少元数据也可以索引，但后续整理和追溯会更困难。不要给多篇实际笔记保留相同模板 ID。

- `source`：原始链接、书名、课程名或“个人记录”；保留发布日期/获取日期等需要的上下文。
- `status: unverified`：收集、摘录或尚未验证的资料，默认使用。
- `status: verified`：说明依据、适用范围或亲自验证过程后使用；不表示永久正确。
- `updated`：最后实质更新日期。`tags` 用于主题线索，不是权限控制。

正文建议写明：核心结论、适用条件、做法/要点、证据与来源、局限与待确认事项。
对个人体验、外部观点和确定事实分别表述。对会变化的价格、政策、健康等资料保留日期及来源，使用时重新核实。

## 两端共用背景

用户确认的长期偏好或架构决策更新到 `CONTEXT.md`；启停方法和路径变更更新到 `docs/CODEX-HANDOFF.md`。
不要把“今天服务已启动”当作长期在线承诺。不要把整段聊天不加整理地写入背景文件。
本库用于保存用户希望长期保留的知识；整理时只记录确有依据的内容，不推断个人隐私或编造经历。
